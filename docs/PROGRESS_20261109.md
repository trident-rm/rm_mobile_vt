## 5. 实时链路根因（P0 问题簇，runs 1-4 + 离线取证）

1. **上游流损伤**：run1 97% corrupt（POC 混沌）；run2（1.5m+遮挡）交付帧反而 99.8% 干净
   （损伤表现为间隙）；run3/4（0.5m）仍有 POC 跳变+0xf → 距离/遮挡非单一变量，
   指向环境干扰或发射端/接收端链路适应行为（待隔离）。
2. **固件 `0xf` 中止**：损伤内容触发 `HEVC_LCU_CHECK status=0xf`（golden POC8、run1 POC24、
   run3 POC269、run4 POC70）→ `Aborting decoding session!`。Copy-Out **不能**修复（固件内容处理错误，
   非引用计数）；ffmpeg CLI 容错吸收错误（管线 0 错误）但**会话已死**。
3. **IRAP 饥饿**：IRAP 仅建链/重建链时发送（实时证实；无周期 IRAP、无主动 IDR 请求手段）→
   会话死后 ~2000 AU 被吞，直到人工重建链。run4 有效显示仅 ~1.2fps。
4. **恢复策略次因**：stall→reset 丢弃缓冲（run4 146 次）；realtime replay A/B 证实即使 0 reset，
   会话死亡仍主导（continue 组 68 帧=0xf 前干净前缀）。
5. 方法论修正：`FileSource.realtime` 默认 False（CLI replay 不复现时间线）；早期"timed replay"
   结论已纠正；吞吐容量测试（无间隙全速）仍有效。
